# 2026-11-09 实机内存根因

本机 Debug / Avalonia 12.0.4 实测确认两条独立的原生内存累积路径。托管窗口可回收、Gen2 正常执行，不能据此排除它们；强制 GC 也不能替原生代码释放遗漏的 COM 引用或清理 CoreText 的字体注册表。

## 1. 无障碍父节点查询遗漏原生窗口引用释放

上游 `automation.mm` 的 `accessibilityParent` 调用 `GetParent()`，父节点是根提供者时再调用 `RootProvider_GetWindow()`。这些接口返回 owned COM 引用，原实现返回 NSView 后没有 Release。窗口关闭后 C++ `WindowImpl` 因引用未归零仍然存活，继续保留 AvnView、输入法和渲染目标，包括 Metal 层与缓冲区。

原生对照中，每关闭一个主窗口仍剩 6 个 COM 引用；36 个托管窗口均已回收。仅修补 `acquire:` 的根窗口分支不能消除它。补齐父节点／根节点与窗口引用释放后，相同关闭操作的原生引用降到 0；堆中的窗口／视图／渲染目标回到当前窗口所需数量。已有节点获取和子节点遍历也平衡对应的 owned 引用，保留 AX 父子关系与窗口定位。

修改位于 `Platforms/MacOS/AutomationLifetime.mm`，沿用精确的 12.0.4 版本保护及方法／字段检查。升级 Avalonia 时必须重新核对接口 ABI。

## 2. 缺少备用家族名使合成字体缓存持续失效

本机 Helvetica / Helvetica Neue 的字形元数据中，`TypographicFamilyName` 为空、`FamilyNames` 为空。上游 `FontCollectionBase.TryCreateSyntheticGlyphTypeface` 只按这两类备用名保存合成结果，遗漏实际请求的 `FamilyName`，随后同样的 SemiBold / Bold 查询再次走 `OpenStream` → `FromStream`。一次 Helvetica Neue 字体流约 301 KiB；PingFang SC 字体流约 12.5 MiB，但其备用家族名完整，能正常进入缓存。

实机调用探针直接记录到同一时刻反复重建 Helvetica Neue；native heap 中新增字体由 CoreText 的 `TInMemoryFontRegistry` 全局注册表持有。只修窗口引用后，字体仍从几十个增长到两百多个，说明这条路径独立存在。

`Platforms/MacOS/MacFontLifetime.cs` 在原系统字体集合中补齐“请求家族名＋样式／字重／拉伸”缓存键，继续使用原查询结果和原集合；不修改字体家族、字重、语言回退，不另建字体缓存。反射只在初始化时绑定受版本保护的缓存访问委托，运行期进行普通委托调用，并串行冷查询以避免重复创建。

补齐后，重复窗口场景中的 `TFPInMemoryFont` 保持 3 个。原生基准还对两个家族的 SemiBold／Bold 各连续查询 50 次，要求复用同一字形实例。Headless 替代字体不能验证本机字体元数据问题，因此该项在原生基准验收。

## 对照结果

修复前首次两小时长测在约 27.3 分钟触及 3 GiB footprint 保护上限而结束，随后用分场景对照定位上述两条路径。

每组约 3 分钟，36 次主窗口打开／关闭，正常阶段不主动 GC，末尾单独进行完整 GC。数值为 physical footprint，单位 MiB；不是 RSS 或托管堆。

| 场景 | 开始 | 自然阶段结束 | 完整 GC 后 | GC.GetTotalMemory 估计值 |
| --- | ---: | ---: | ---: | ---: |
| 修复前 | 478.9 | 992.6 | 914.2 | 78.7 |
| 仅修无障碍引用 | 486.0 | 711.5 | 597.5 | 96.1 |
| 两处均修复 | 454.2 | 527.6 | 428.1 | 76.6 |

两处均修复的 36 个关闭窗口：托管弱引用存活 0，原生引用未归零 0。字体对象数量稳定。改变系统字体、切换软件渲染、手动拆除 Metal 层或单独释放输入法都不是这两条根因的完整修复；这些探索性生产修改均未保留。

后续独立复现确认：本机 .NET 10.0.5 的 `GC.GetTotalMemory(false)` 存在重复估计，上表末列保留历史原始值，不能按实际存活字节解释。新日志另记录与 GC index 对齐的 `liveAfterGcBytes`。

常规 fast 测试：1150 通过、2 跳过、0 失败。完整原生回归另验证 200 次字体查询复用、36 个页签／3 个设置窗口／30 个任务负载全部回收，保留任务摘要 30 条；第三轮关闭页签相对第一轮的托管增长仅 0.20 MiB，最后空闲与完整 GC 后 footprint 约 343 MiB。此前两小时复测在约 34 分钟时提前退出，没有完成验收，不能算通过。随后按用户指定，以真实下载目录完成图片混合及 PDF 专项共约 8.3 分钟回归，关闭对象回收通过，详情见 [真实目录实机回归](LocalRun-20261109.md)；该短测不代替两小时验收。

诊断只记录匿名生命周期、操作阶段、GC、内存和原生类数量，不记录用户文件路径、名称或内容。原生堆只提取 `heap --noContent` 的指定类数量／字节数。
