# 2026-11-09 真实下载目录实机回归

本机 macOS 27.0.1、arm64、32 GiB 内存，当前源码构建的 Debug 原生 Avalonia 应用。按用户指定使用真实下载目录及其子目录，实际浏览、滚动、展开目录、开关页签／窗口和预览文件。测试配置及缓存按项目规则隔离；不生成替代文件，不执行真实文件移动、重命名或删除，报告不保存文件名、真实路径或预览内容。

## 数据与操作

限深、限时扫描 200 个目录，选主目录及三个条目较多的子目录。主目录实际显示 592 项，候选目录元数据计数分别为 594、329、178、144，元数据计数与界面计数会因隐藏项和过滤而不同。图片测试候选有 176 个可预览文件，PDF 专项使用 34 个真实 PDF 的目录。

PDF 专项另执行 166 次滚动、8 次完整目录从头到尾滚动。两轮均执行固定字体复用检查及真实 AX 父节点／窗口关系检查；PDF 专项确实创建了 24 个文档预览控件，覆盖文档渲染路径。

## 结果

两轮 `verification.json` 均确认完成，进程退出码 0，无超时、无诊断日志丢失。最终完整 GC 后，68 个已关闭页签与 34 个已关闭窗口／设置窗口的弱引用全部归零；34 次原生窗口关闭引用检查全部为零。无弱引用跟踪淘汰。

图片场景原生 `TFPInMemoryFont` 全程保持 3 个。PDF 加载期间字体数量曾升至 47，后续采样回落到 3，没有重现原先每关闭窗口都累加的 UI 合成字体模式。两轮末次原生采样的 C++ `WindowImpl` 均为 1；图片场景视图和渲染目标为 1，PDF 场景为 2。PDF 的该次采样早于最终完整 GC，未取得其 GC 后的原生类数量，因此不据此声称所有原生对象均已回到一份。

| 内存指标（MiB） | 图片混合场景 | PDF 专项 |
| --- | ---: | ---: |
| 初始 physical footprint | 434.78 | 424.35 |
| 过程峰值 physical footprint | 756.17 | 884.60 |
| 自然阶段结束 physical footprint | 652.08 | 684.80 |
| 完整 GC 后 physical footprint | 644.19 | 627.38 |
| 完整 GC 后 GC.GetTotalMemory 估计值 | 115.36 | 101.56 |
| 完整 GC 后托管堆已提交量 | 168.12 | 126.83 |
| 完整 GC 后托管堆碎片 | 92.02 | 61.52 |

回收后的总占用仍高于初始值，不能据此宣称整体内存已无增长。托管堆保留及碎片已有明确记录；图片场景的原生 malloc 最后采样约 97 MiB 存活分配、66 MiB 碎片，而最初约 90 MiB 存活分配、21 MiB 碎片。保留页、碎片与进程 footprint 是不同口径，不能简单相加，也不能把全部余量都归为缓存。

后续独立复现确认本机 .NET 10.0.5 的 `GC.GetTotalMemory(false)` 存在重复估计；上表 115.36 / 101.56 MiB 是原 API 返回值，不能直接解释为真实存活对象总量。新日志用与 GC index 对齐的 `liveAfterGcBytes` 补充判断。

本轮结论是：真实文件场景未重现已修复的窗口引用与 UI 字体累积路径，关闭对象回收检查通过；约 8 分钟的短测不足以排除其他缓慢增长。此前两小时测试在约 34 分钟提前退出、没有完成验收，不能算两小时通过，目前也没有两小时真实目录测试的通过结论。

本轮重新运行 fast：1150 项通过、2 项跳过、0 失败。构建成功，Python 脚本语法及差异空白检查通过。

## 日志与复现

原始数值报告、阶段采样、程序集哈希及诊断日志保存在项目 `outputs/memory-real-downloads-20261109/`，未导出用户文件或缩略图。两轮累计检查 4370 条诊断记录，对扫描所得 1694 个长度至少 8 字符的文件名进行匹配，下载目录路径及文件名匹配均为 0；诊断丢弃数为 0。

使用 `MACEXPLORER_MEMORY_REAL_ROOT="$HOME/Downloads"` 运行 `run-soak.py` 可复现实文件场景；再设置 `MACEXPLORER_MEMORY_PREVIEW_KIND=pdf` 可复现 PDF 专项。配置变量通过进程环境传递，不写入运行配置或诊断日志。原生 heap 仅保存指定类的数量和字节数。

运行器已补齐提前退出判定：即使应用退出码为 0，缺少完成验收也会以失败结束，避免将中断的长测误记为通过。
