# 2026-11-09 常驻内存日志覆盖与开销检查

现有常驻数据足够分析趋势、关联操作、区分存活对象／碎片／缓存、筛选关闭后未回收的对象。它并非全量分析器：各类 GC 只保留每周期最近一次快照，不覆盖每次 GC；原生分配栈、GPU 分配和具体对象持有链仍需按需现场取证。为此默认开启分配跟踪或堆转储会增加开销，并可能保存用户内容，未采用。

## 本次补强

- 仍每 30 秒采样，不强制 GC。补充 JIT IL／方法计数、Skia CPU 资源／字体缓存，以及运行时 GC 配置；明确 IL 字节不等于原生代码页，CPU 缓存也不等于 GPU 内存。每文件带独立会话上下文，UI 周期记录字体表 POH 修补状态。
- 总预算约 16 MiB／8 文件，趋势独立占 4 MiB／2 文件，操作事件占 12 MiB／6 文件。每文件 2 MiB；满一天也轮转。最多保留最后写入后 7 天，启动、轮转及持续写入每小时在后台清理，关闭应用时不额外创建清理守护进程，下次启动继续清理。容量限制可能先于时间限制淘汰数据。
- 只删除本程序规范命名的普通日志，保护仍打开的文件、手工文件与符号链接；无法腾出空间或写盘失败则停止本次诊断，避免无限增长和反复报错。目录权限不允许时无法强行删除过期数据。
- 队列最多 128 条，操作最多占 96 槽，为趋势预留余量。固定秒窗口操作上限 128 条，队满／限流在序列化前拒绝，单条最多 8192 字符。队列只存字符串，不保存业务对象；后台批量 Flush，无操作线程文件 I/O。
- 缓存统计使用非阻塞锁，忙则标记 `Skipped`，不误报缓存清空。Git 每仓库只抽样最多 32 个路径长度估算字节，不遍历全部文件。弱登记源上限 512，生命周期弱登记上限 2048，已结束元数据最多观察 24 小时；过期／淘汰均计数，不释放业务对象。
- 生命周期锁内不做 JSON 序列化；停用后已排队的 UI 观察直接退出，UI 观察异常被隔离；周期原生窗口观察最多 8 个可见窗口。`memory.observer` 记录诊断自身的 worker/UI 耗时，健康计数记录缺失和清理失败。

## 验证结果

新增检查覆盖启动／空闲过期清理、一天轮转与上下文、活动日志保护和容量不足、符号链接保护、写入失败自动停用、事件风暴与趋势预留、缓存锁忙跳过、生命周期元数据过期，以及停用后的 UI 回调取消。快速测试包含这些检查，完整测试交由 CI。

最终 fast：1163 通过、2 跳过、0 失败，包含 9 个新增日志安全检查；Python 脚本语法及差异空白检查通过。

真实下载目录只读复测运行约 2.14 分钟，8 次目录访问／166 次滚动、16 个页签、4 个主窗口、4 个设置窗口及 42 次预览选择，完整结束且退出码 0。关闭对象的托管弱引用及 8 次原生关闭引用检查均归零。趋势日志约 32.6 KB、事件约 328.4 KB，5 次进程采样的队列、限流、超长、序列化失败、源淘汰与清理失败计数均为 0。

5 次 `memory.observer`：首次后台 19.48 ms、UI 6.18 ms；预热后后台 0.82–2.34 ms、UI 0.18–2.80 ms。均为每 30 秒一次的观察，不是逐帧开销；后台计时不包含独立写盘线程，UI 计时不包含全部操作事件的序列化。只能代表本轮短测，不能当作所有机器／工作负载的开销上限。事件的序列化仍有有限成本，限流和队列上限用于控制突发情况。

数值产物及实际运行 DLL 哈希归档于 `outputs/memory-logging-audit-20261109/`，不归档应用、缩略图缓存或原始堆。该短测验证接线与正常负载，不等于两小时验收；长期分析仍应结合缺失／淘汰计数和现场资料。

归档 1325 条 JSONL，检查下载目录路径与用户主目录路径均为 0；用 1940 个文件／目录名词条复核，只有固定系统 VM 字段、原生区域类型、事件名称及窗口类名的静态词汇碰巧匹配，没有用户文件派生字段。
