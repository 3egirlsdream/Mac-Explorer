# Issue #11：页签拖动导航与交互开关

补丁基线：`48e95ae20f8ab8acd885809aaa3bb45f3c0de470`（v1.0.42）。
范围：实现三项交互；不包含自定义快捷键，不修改版本号、依赖或 macOS 打包配置。

## 用户行为

| 功能 | 行为 |
| --- | --- |
| 拖动文件经过页签 | 立即激活鼠标下的页签，显示该页签内容，再继续拖入内容区选择落点。 |
| 松手位置 | 松在子文件夹上投递到该文件夹；跨页签松在背景投递到目标目录；纯本地在源目录背景或页签栏松手不执行文件操作。 |
| 文件区操作 | 纯本地拖放执行移动，不通过 Option/Alt 切换为复制，同页签拖到子文件夹保持有效。源或目标涉及 SFTP 时保持原有复制逻辑，源文件保留。 |
| 删除确认 | 设置 → 通用 → 文件操作 →「移到废纸篓前确认」，默认开启。 |
| 双击返回 | 同组设置中的「双击空白处返回上级」，默认关闭。 |

Finder 标签聚合页的背景拖入仍只添加标签，不搬动文件；侧栏已有拖放语义不变。

## 实现与保护

- `FileTabDragNavigation` 通过页签原有的双向选择绑定激活工作区，不重新发起拖动，不从新页签的选中项重建拖动数据。普通文字拖动、模态阻塞和全局搜索覆盖时不触发页签激活。
- `FileDropPolicy` 统一悬停指示和松手操作，拒绝拖到自身/后代目录；移动时跳过同目录项目。悬停阶段不读取磁盘；最终落下时检查目录存在与目标可写信息，并保留原有操作链路的异常/重名处理。
- 松手时重新命中测试，移除“回退到此前悬停文件夹”的目标选择逻辑，避免最后放到空白处却进入之前的目录。
- 两个设置分别保存在 `confirm_before_trash`、`double_click_empty_area_go_up`。执行时读取共享设置缓存，已打开的其他页签/窗口立即采用新值，重启后保留。
- 工具栏、菜单、键盘删除仍经过同一个请求入口。请求时固定待删选中项，避免弹窗期间选择改变导致删错项目；取消清除待删快照，进行中的删除不会重入。
- 删除确认开关只跳过可恢复的本地移到废纸篓提示。SFTP 删除实际上是直接删除，因此仍强制确认，并使用真实后果提示；永久删除、清空废纸篓、删除标签的独立确认不被此设置关闭。
- 双击返回只作用于无修饰键的背景双击。文件/文件夹、列表行内空白、分组标题、滚动条、按钮、编辑中和加载中不触发该操作；列表/网格、分组及 FastFileList 开关均覆盖。
- 返回行为复用原有 `NavigateUpAsync()`，保持根目录、归档、远程目录等现有导航语义。
