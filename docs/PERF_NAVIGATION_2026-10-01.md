# 进入文件夹卡顿与文件夹图标修复验收

2026-10-01，Apple M5／32 GiB，macOS 27.0，arm64 Release，.NET 10。基线为 `6baa8b1` 加当前工作区已有改动，修复后保留这些改动重新运行相同数据。另从 `6baa8b1` 导出独立副本，仅应用本次修复，验证构建、完整测试和原生图标，不依赖尚未提交的 App Store 改动。

## 结论和改动

进入目录时的秒级冻结属于缺陷。图标模式同步测量全部不同文件名，十万项每次占用界面线程约 30 秒；列表导航还同步保存 `navigation_last_directory`，与后台搜索索引争用 SQLite 写锁。采样栈明确落在 `FileListViewModel.NavigateToAsync → SettingsService.Set → Persist → SqliteCommand.ExecuteNonQuery`，包含界面线程上的 SQLite 等待。

- 网格统一预留两行名称高度，只为可见项目创建字形布局。取消全目录文件名高度缓存，保留分组、字体响应、命中、选中与滚动几何。短名称也使用两行空间，避免滚动时高度跳动。
- 上次目录立即更新内存，后台串行合并写入数据库，正常退出时等待最后一次保存。前进／后退及返回首页共用此路径。其他设置继续同步保存，现有隐私写入语义保留。
- 恢复 Finder 文件夹外观：从当前系统的 `GenericFolderIcon.icns` 读取并按尺寸缓存；独立原生入口放在已有动态库中，构建不再复制系统图案进应用包。失败时继续使用已有回退图标。

## 测量方法

通过 `Tools/Testing/run-isolated.sh` 启动新构建 `.app/Contents/MacOS/FastListBench`，使用真实 `App`、主窗口、目录枚举、搜索索引、数据库和 Quick Look 缩略图服务。每次创建独立目录，包含 1,000／10,000／100,000 个名称不同、含中文的零字节 `.txt` 文件。

三种模式各测索引 Ready 与主动 Refresh 两组，每组重复三次，共 54 次。`busy` 只表示请求了刷新；扫描可能在后续重复前结束，实际状态保存在 CSV 的 `phaseAtStart`／`phaseAtEnd`。每次确认数量完整、名称排序稳定。测试目录内的配置与缓存从索引范围排除，避免测试缓存触发自身扫描。

`firstFrameMs` 从调用导航开始到完整目标目录第一次 `FastFileList.Render()`，包括枚举与排序等待；它不含鼠标投递延迟，也不是 GPU 呈现时间。`navigationHeartbeatMaxMs` 为 16ms UI 定时器最长间隔；`commitMaxMs` 为快照提交时间。滚动每步 35px、等待 16ms，共 30 步，统计绘制 CPU 时间与心跳。

## 回归与原生验收

- 大网格回归：十万不同名称布局不生成离屏名称缓存，渲染只创建可见名称；两行名称、18px 字号与尾部命中均通过。
- 数据库争用回归：另一个连接持有写事务时，延迟保存、读取缓存和读取全部设置保持可响应；释放事务并 Dispose 后数据库保存最新目录。
- 当前工作区完整隔离测试：`Total: 1232, Errors: 0, Failed: 0, Skipped: 4, Not Run: 1`。未配置 Store 签名沙箱、Paramiko QA 环境及实机 RAW 样本的测试略过。首次运行因临时 artifacts 路径缺少测试仓库定位环境变量而中止，补齐环境后全量重跑；该配置错误不作为应用缺陷。
- 独立提交副本完整隔离测试：`Total: 1188, Errors: 0, Failed: 0, Skipped: 1, Not Run: 1`，实机 RAW 样本未提供。Release 构建及严格签名检查通过；构建保留既有分析器、弃用与 XAML 警告。
- 从独立副本的原生 `.app` 克隆唯一测试 bundle ID，仍通过隔离启动器运行：浅色／深色、约 1000px 窄窗口、中文长名称、图标／列表／树形、双击进入、后退和滚动均实际检查。36／112／512px 原生文件夹输出均为有效 PNG，外观为原系统蓝色文件夹。

本次仅验证本机 arm64、本地目录和上述文件规模。未把这些结果外推为网络盘、Intel、Store 沙箱权限或所有 RAW 的验收，也未对索引覆盖与稳定排序做行为变更。提交限定于本次修复、回归测试、基准工具与报告；其他已有工作区改动保持原状态。
