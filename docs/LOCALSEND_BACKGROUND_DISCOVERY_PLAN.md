# LocalSend 后台发现与本进程设备优先

## 目标与边界

LocalSend 开启后，即使从不打开“发送到”菜单，也在后台发现设备并通过官方 `/api/localsend/v2/register` 公告本机身份、实际端口和协议，让可达的手机认识电脑。本进程已经成功验证的设备优先复查、优先显示；其余地址后台渐进搜索。多窗口和页签共用现有应用级 `ILocalSendService` 单例及一个接收端。

不新增数据库表、后台守护进程、通用调度框架或设置项。保留既有接收确认、文件安全、旧版 info 兼容、实际端口公告和手动地址功能。不能保证跨网络隔离或对任意非默认端口的未知设备盲扫成功。

依据：https://github.com/localsend/protocol#3-discovery 。本次调整发现任务的触发、共享和资源预算，不改变传输协议。

## 设备优先与显示

1. 本进程、当前网络已经验证且仍新鲜的设备立即显示，按最近成功优先；展开菜单同时请求优先复查与注册。仅扫描过但未成功验证的地址不视为设备。
2. 过期或曾失败的设备保留有上限的候选记录，优先复查，成功后再作为可发送设备显示；不能长期显示已离线设备。已有持久历史作为次级候选，不作为在线证据。
3. 同一指纹更换 IP/端口更新原设备，不重复项；每次向手机注册使用当前本机端口、别名和指纹。网络切换立即失效旧在线状态，仅复用匹配网络的历史候选。
4. 菜单从共享结果获取首屏和增量更新。关闭菜单只取消该订阅/加载，不能停止应用后台发现；迟到回调仍必须被菜单请求版本与取消令牌拦截。多个窗口、刷新和反复展开不能叠加扫描或重置大网段扫描进度。

## 调度与资源预算

在现有服务内部保留一个受生命周期管理的发现协调任务，优先复用现有缓存和扫描函数，不复制设备列表或建立通用工作队列框架。

- 启动/重新开启后异步开始；不得阻塞首窗或 UI 线程。网络变化合并处理，停止并等待旧一代任务，再启动新一代。菜单请求只唤醒/提高已知候选优先级。
- 顺序：本进程已验证候选 → 当前网络相关的历史候选 → 本机和已知设备附近网段 → 既有受限私网扩大范围。每一批之间检查高优先候选，不能让已知手机等完整网段扫完。
- 初始硬预算：全服务 TCP 探测并发至多 16、设备信息/注册 HTTP 并发至多 4；陌生地址新建 TCP 探测至多 64 次/秒。所有发现来源（含 UDP 引发注册）共用有界预算，不产生无界 Task.Run、排队或 socket。
- 陌生地址流式分批（每批至多 256），批间让出调度；连续扫描约 20 秒后至少休息 5 秒。每轮总候选仍至多 65,536，保留推进位置；完成一轮后至少休息 5 分钟，避免重复扫首段与忙循环。多接口公平推进、排除虚拟桥接与自身，沿用现有物理网络范围限制。
- 已知在线设备约 60 秒重新注册；失败按 15/30/60/120/300 秒退避并加小幅抖动。唤醒/手动刷新允许提前一轮，但同一目标短时间重复请求合并。已知复查不受整轮扫描完成阻塞。
- 正在传输时暂停陌生地址扩大扫描，保留必要的低频已知设备注册；无可用物理网络时等待，不能持续高频遍历接口。
- TCP 初探保留短超时；HTTP 验证有独立超时、64 KiB 响应限制和证书指纹检查。资源上限须覆盖恶意公告/慢 HTTP 情况。失败逐地址日志仅 Debug，不刷正常日志。
- 缓存与候选状态显式有界（建议最多 128 个设备），清理过期条目；不为每个地址分配常驻任务/定时器，不每次注册写配置，不在热路径反复枚举网卡或计算证书指纹。限速参数可依据测量下调，若上调需报告依据并重新审查。

预算是上限而非性能验收结果。首次空历史跨子网发现可能需要数分钟甚至更久；不以高并发换取无依据的“秒发现”承诺。

## 生命周期与并发

- 关闭功能和退出：先取消发现、订阅、UDP 接收及在途探测，等待受管任务收尾，再释放 socket、CTS、证书、HTTP handler 和监听。退订 NetworkChange 事件，不残留回调持有窗口或服务。
- 禁止持有生命周期锁等待内部又需要同一锁的任务；避免取消后回调写入新一代缓存。网络代次/令牌一致性保证跨网络迟到结果不回写。
- 关闭/开启、网络抖动、菜单取消、服务 Dispose 可重入调用不死锁、不重复启动；已释放实例不得被迟到事件重启。
- 保持设计器与非桌面测试宿主不启动真实后台网络的既有边界。测试必须显式限制接口/候选，不能每个单元测试都扫描真实局域网。

## 开发与验收

开发在当前 FKFinder 工作区执行，先记录本轮基线并保留 RAW/LibRaw、发布脚本等既有未提交修改。遵守 AGENTS.md，必要 UI 修改沿用全局菜单与设置组件。默认不提交、不推送、不发布。

针对性自动测试：不调用 DiscoverAsync 也会注册；已知设备先返回并优先复查；多订阅只运行一轮；取消菜单不停止后台；IP/端口更新；失败退避、在线过期；扫描推进不饥饿；并发和速率上限；传输期间退让；网络切换旧结果丢弃；关闭/重开/重复 Dispose 后任务和端口释放；UDP 突发仍有界。用有限替身/本地端点与可控时间验证，避免堆叠只断言常量的测试。

真实验证通过 `bash Tools/Testing/run-isolated.sh <新构建 .app/Contents/MacOS/MacExplorer>`，构建使用 `-p:SkipMacOSReleaseDMG=true`。记录空配置、不展开菜单的后台发现/注册；手机最后提供地址 172.20.235.80 仅用于核对，不得硬编码或预置到扫描输入。记录已知设备再次出现、关闭后无继续探测、多个窗口仍一个服务。手机显示需真实界面确认，注册 HTTP 成功不冒充手机 UI 或文件互通通过。

性能：对同一新包隔离实例，比较功能关闭基线、空网段扫描、已有设备稳定状态；至少各 60 秒采样 CPU、RSS、线程/FD/socket 数，并检查反复开关/网络重建后计数是否持续增长。明确样本、测量时长、噪声和未验证项目，不把短时平稳当成绝无泄漏。记录实际扫描请求率/并发峰值及 UI 主线程不被等待的证据。优先定向测试与 Debug arm64 构建，必要发布构建验证变更兼容性。
