# FastFileList 实施记录 · 2026-09-08

开发分支：`codex/fast-file-list`。v1.0.37 起默认开启高性能文件列表，覆盖明细、分组和网格；已保存的手动关闭设置继续生效。入口是「设置 → 文件显示 → 高性能文件列表（试用）」，可随时关闭并回退原列表。下文保留开发各阶段的验证记录，其中默认关闭及未提交状态均指对应阶段。

当前自绘路径覆盖本地、远程、压缩包、回收站、AI、收藏夹和标签的文件列表，支持普通明细、分组明细、图标网格和分组网格。首页继续使用原有布局。完整的逐行 VoiceOver 支持尚未实现，因此保留回退开关。以下前两轮记录保留各自的验证范围，最新接入结果见文末。

## 实现与方案调整

- `Controls/FastFileList.cs`：固定 30 DIP 行高，使用 `Control.Render` 与 `ILogicalScrollable`。只绘制可见行，滚动、命中测试、框选和重命名位置使用同一套行坐标。
- `Controls/FastFileListImages.cs`：可见区请求延迟 100 ms 发起，离开可见区即取消。缩略图按路径、修改时间、大小、来源和目标像素缓存，过期结果不会填到新文件；拥有的位图总量限制为 32 MiB。类型图标与共享 `SvgIconCache` 的所有权分开。
- 文本缓存按文件路径和元数据复用，限制 1,024 行；另有最多 1,024 项的重复单元格文本缓存。字体、刷子、列宽和显示缩放变化会使相关缓存失效。只订阅可见文件的属性通知。
- `Views/FileListView.FastList.cs`：接入现有选择、菜单、打开、拖放、键盘和重命名。Enter 继续表示重命名，空白处单击和拖动框选沿用原有行为。编辑时只创建一个真实 TextBox。
- 同时处理初次绑定、`Entries` 替换和集合原地变更，覆盖排序及筛选；不只依赖目录的 `SnapshotApplied` 事件。现有快照滚动锚点继续生效。
- 批量选择使用一次集合通知，避免全选或大范围框选时反复更新整批状态；修正向上 Shift 选择后锚点漂移。

借鉴 FileMate 的重点是固定行高、按可见范围同步提交内容、减少逐行控件工作。本次没有引入 Rust，也没有采用按行索引保存长期图片引用的方案。目录扫描和排序管道沿用已有实现，因此不把此次修改描述为扫描速度优化。

- 自动化工具的修饰键输入曾额外产生 `A + Meta`，导致在 `R + Meta` 前执行全选。通过临时事件跟踪确认后已移除跟踪代码；刷新快捷键另用直接按键事件回归，验证两个选中路径和滚动位置保持。没有在产品代码中加入对该工具行为的特殊处理。

Release 原生基准使用 100,000 条合成数据，视口 1,000 × 720，24 个可见行，执行连续跨屏滚动、随机跳转和六次快照替换：

| 指标 | 本次结果 |
|---|---:|
| 建立十万行路径索引 | 9.22 ms |
| Render 样本 | 360 |
| Render P50 | 3.82 ms |
| Render P95 | 5.99 ms |

原方案的 `Render ≤ 2 ms` 和 `≥ 55 FPS` 目前不能标记为验收通过：前者在跨屏冷文本测试中尚未达到，后者尚未测量。刷新闪烁和快速滚动的长期稳定性仍需真实工作目录持续体验；当前证据只支持上述已验证范围。

## 后续调整：立即进入目录、骨架屏与工具栏稳定

- 初次进入路径时，原先同步执行的 macOS 文件夹显示名查询和磁盘空间读取已移到后台。路径栏先显示可用名称，查询结果只更新仍然对应的路径栏；磁盘空间更新也检查请求代次。
