# LocalSend 跨子网首次发现诊断（2026-10-19）

结论：本机与目标跨 /24 子网，默认组播不能作为跨路由发现机制；当前单播后备扫描的候选顺序、每批 4 个地址和 20 秒扫描 / 5 秒休息共同造成长时间排队。目标包含在扫描范围内，但首次探测需等待约五分钟；目标锁屏后的不可达又会使这一轮错过它。锁屏原因仅为结合用户解锁后恢复的推断，未读取手机系统状态。

## 现场与验证方法

- 本机物理接口 en4：172.20.202.91/24；到 172.20.205.32 的实际路由经 172.20.202.1。
- 目标 HTTPS 53317 的 v2/info 返回 200，alias 为“快速的土豆”，deviceModel 为 Xiaomi，version 为 2.1。
- 20 次 TCP 连接全部成功，最小 3.05 ms、中位 3.66 ms、最大 66.22 ms，低于当前 250 ms 预探测时限。
- 探针引用当前 Debug 程序集，调用真实 LocalSendService，通过 Tools/Testing/run-isolated.sh 启动。设置使用内存替身，证书和默认路径位于独立测试目录；不发送文件。
- 自动发现基线不设置 ScanSubnet，不注入目标 IP，不加载正式设备历史，不覆盖物理网卡枚举。目标 IP 仅用于观察是否出现在快照中。
- 现场还有两个运行中的 Mac Explorer 实例，基线可以经其公告发现本机设备；这是正常现场干扰，已在日志保留。

## 代码原因

1. LocalSend 默认组播为 224.0.0.167:53317。IANA 对 224.0.0.0/24 规定不跨路由转发，因此直连 HTTPS 成功不代表组播发现能到达该目标。未对网关抓包，不能断言具体网络设备的配置。
2. FastScanCandidates 只将本机 /24、已知历史 /24 和可选配置放入快速列表。此现场空历史时快速列表为 253 个地址，不包含目标。
3. ExpandedScanStream 从本机 /20 的网络起点顺序遍历：172.20.192.0 起，随后才扫同一 RFC1918 /16 的其余地址。目标排在整轮第 3360 个，非漏出扫描范围。
4. RunDiscoveryAsync 虽调用内部 16 并发的 ScanCandidatesAsync，实际每次只给 4 个地址，并等待全部结束才取下一批；实际未知 TCP 峰值只有 4。每 20 秒扫描后还暂停 5 秒，同一协调任务需等待已知设备 HTTPS 注册，慢请求会继续拖延扫描。
5. DiscoverAsync / 菜单刷新只读共享快照、调用 RefreshKnown；它不提高未知扫描优先级。ScanSubnet setter 只保存设置，而快速候选在当前后台代次启动时捕获，因此运行时修改高级网段也不会立即重建扫描列表。
6. 现有 UnknownProbeRateAndConcurrencyStayWithinBudget 测试直接传 96 个回环地址到 ScanAddressesAsync；它未经过后台每批 4 个的调度。候选范围测试只检查包含性，未检查真实后台首次发现耗时。

## 知乎讨论的参考价值

已通过浏览器读取用户提供的 [知乎讨论](https://www.zhihu.com/question/633611887)，并核对 SomeBottle 作者的 [LocalSend Switch 项目](https://github.com/SomeBottle/localsend-switch)。

- 设备信息交换 + 单播注册：有帮助。固定地址节点交换参与端的 IP/端口，客户端所在主机再向对端发起注册，避免依赖跨子网组播和遍历未知地址。可作为固定办公网络、可部署辅助程序的可选方案。
- 部署前提：需要有设备信息来源、参与端或辅助节点配合，并配置交换节点。仅给 Mac 增加这套逻辑，无法保证凭空得知另一 VLAN 内未参与交换的原版手机地址。作者实现强调注册应从客户端所在主机发出，因为接收方按 TCP 来源地址识别设备；简单从中心服务器代发会注册成服务器地址。
- 配置普通组播路由：不能直接当成默认 LocalSend 的通用修复。IANA 明确 224.0.0.0/24 不应跨路由转发，与单纯 TTL 大小不同；需要专门的应用级发现代理或参与端协调，不能只把 TTL 调大或笼统开启组播。
- 手动 IP：本次已实测有效；IP 改变后仍需重新发现。

当前程序已有定向 HTTPS 注册能力，可以借鉴交换“设备地址”的思路；本轮定位出的每批 4 个、顺序扫描和高级网段不更新仍需在本程序中独立修复。

## 修复方向

让未知地址扫描能够保持有效的有界并发，并让已知设备注册独立及时调度；调整相邻子网候选顺序以降低附近子网的首轮等待；用户修改高级网段或主动刷新时更新扫描候选。需增加走真实后台路径的吞吐、慢已知设备和网段修改回归，继续保留速率上限、取消、证书指纹核验与网络代次隔离。

临时绕过：手动输入 IP；或保存高级网段 172.20.205.0/24 后关闭再开启 LocalSend。

## 本程序修复与复验（2026-10-19）

按用户要求完成本程序修复，没有引入交换节点。

- 将未知地址扫描从已知设备注册协调任务中分离；两者仍归属同一个网络代次，关闭和网络切换会取消并等待全部任务结束。未知扫描恢复 64 个地址的工作批次，TCP 上限仍为 16，HTTP 共用上限仍为 4，未知地址仍按 16 ms 最小发起间隔限速。
- 本机 /24 仍优先；扩展范围在同一私有 /16 内，先按距离排序附近 /20 的 /24 子网，交错各子网的主机地址，再扩大至其余范围。未硬编码手机 IP 或 205 子网。
- 高级网段保存新值后取消当前未知扫描批次并重建候选；无需重启服务，不清空在线设备。菜单订阅/刷新会重播公告并优先重扫当前快速候选，保留尚未完成的扩展扫描位置；完成后的扫描也可被刷新唤醒，无需等待五分钟冷却。
- 新增真实后台调度回归：慢设备注册期间仍推进至少 40 个未知探测、TCP 峰值达到 8–16；网段修改/清空即时替换候选且保持同一协调任务；刷新唤醒已完成轮次。补充附近子网交错顺序与去重检查。
