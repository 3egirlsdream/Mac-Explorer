# LocalSend 跨子网扫描调度与手机实测（2026-10-22）

> 本文记录第一阶段的实现与实测；最终保留的实现、限速及未通过的 10 秒实验见 [后续验收记录](localsend-discovery-under10-20261022.md)。本表不代表最终代码已重新完成实机验收。

## 修改

- 移除后台 64 地址整批等待，以持续消费的异步候选流运行最多 16 个 TCP 探测。一个探测完成即可补入下一地址。
- TCP 探测与 HTTPS 验证分离，使用容量 16 的有界队列；每个扫描流水线最多 2 个验证，全部 HTTP 请求仍受共享 4 并发限制。慢验证不会占住 TCP 探测工作位，队列满时施加背压。
- 活跃扫描收到刷新时保留枚举位置，仅唤醒和续扫，不再插入第二份快速范围。完整轮次结束后的刷新仍可开始新轮次。
- 修改自定义网段时取消并排空当前流水线后重建候选。网络切换和关闭继续等待所有阶段与外部扫描结束。
- 保留 16 ms 发起间隔、TCP 250 ms 超时、后台验证 3 秒超时、20 秒扫描/5 秒休息、TLS 指纹核验及现有范围和顺序。未增加手机地址或特定网段规则。

## 手机对照方法

本机物理接口 en4 为 `172.20.202.91/24`；到手机 `172.20.205.41` 的路由经 `172.20.202.1`。手机 `/api/localsend/v2/info` 返回 alias“快速的土豆”、设备 Xiaomi、协议版本 2.1；独立 5 次 GET 全部成功，中位 26.4 ms。

探针直接引用当前 Debug 程序集并调用真实 LocalSendService，每轮经 `Tools/Testing/run-isolated.sh` 创建全新配置目录，设置使用线程安全内存替身。开始时确认 `SCAN_SUBNET='' HISTORY_PRESENT=False`；使用系统实际网卡与正常组播，不覆盖接口、候选或 TCP 探测，不调用手动地址连接，不发送文件。监听 TCP 使用随机端口以兼容现场已有应用。

目标地址只通过探针命令行传入，用于在 `DiscoverAsync` 的设备快照中判断成功，不参与候选生成、设置或设备历史。计时从 `StartAsync` 前开始，到首次设备快照包含手机为止，包含初始化、TLS 核验、注册和快照通知时间。

现场其他 Mac Explorer 实例仍在运行，可能通过公告提供本机其他接口地址；日志保留这些发现，未为获得更好数字关闭现场实例。隔离配置不是网络沙箱。
