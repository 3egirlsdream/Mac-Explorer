# 大批量粘贴、外置磁盘与界面响应排查（2026-11-13）

本次确认并修复了长文件名复制失败、目录权限失败后重试不完整，以及大批量任务记录和粘贴准备阶段的阻塞问题。外置盘已有目录实际复制到本机后内容一致。另确认数千项一次性写入 macOS 系统剪贴板仍存在短暂停顿，此项未作为已修复处理。

## 环境和边界

- 外置盘 `/Volumes/External`：USB、APFS、可读写，所有权检查关闭，空间充足；未进行磁盘修复、格式化或卸载。
- 外置源目录 `/Volumes/External/归档11.14`：81,111 个普通文件、191 个符号链接、9,890 个子目录，普通文件合计 401,081,043 字节。
- 仅复制，不删除、移动或改写源文件；目标、配置、数据库和日志均使用 `run-isolated.sh` 创建的独立临时目录。
- 使用新构建 Website Debug `.app/Contents/MacOS/MacExplorer` 的真实窗口。独立命名剪贴板覆盖多文件原生 URL 写入和外部 URL 采纳，不覆盖用户系统剪贴板。
- 未从已有崩溃日志找到能对应用户那一次粘贴失败的异常。因此下面是已复现的缺陷及当前磁盘验收，不能据此认定原始失败只有一个触发原因。
- 本次未覆盖 exFAT、NTFS、磁盘拔出、磁盘损坏、空间耗尽或 App Store 沙盒授权，也未替换用户正在运行的实例或发布新版本。

## 已修复

1. **合法长文件名因暂存名称超限而失败。** 原实现在完整目标文件名后追加任务 ID 和 `.fkfinder-tmp`，244 字节的合法文件名会产生超出文件系统组件限制的暂存名称。超过长度时改用目标路径摘要和任务 ID 生成短暂存名称，保留原始目标名称、不覆盖已有文件，保留取消清理和暂存文件身份校验。
2. **目录读取失败后的重试不可靠。** 不完整的扫描结果不再作为完整清单复用；权限修复后重试重新扫描。数据尚未完整复制时不提前恢复目录的只读权限。目录属性恢复可能改变创建时间，而创建时间属于原生身份的一部分，属性写入成功后同步更新本任务持有的身份记录；重试仍拒绝被其他目录替换的目标。
3. **每个文件完成后全量整理任务结果。** `FileTaskContext.ReportItem` 原先每次遍历并移除旧结果，再复制全部明细并通知界面；4000 项回归记录到 4002 次快照。现在按源路径索引更新，明细快照最多每 50ms 发布一次，任务结束强制发布最终结果。新增索引纳入失败断点内存预算，释放时一并清理。
4. **粘贴前在主线程逐个访问磁盘。** 剪贴板采纳不再用同步 `File.Exists` / `Directory.Exists` 过滤路径；离线或不可读的源由后台任务明确报错，不再静默遗漏断链。入队路径规范化移到后台。原生 URL 构造使用显式目录提示，避免隐式访问文件系统。
5. **原生文件身份查询缺少后台自动释放池。** 为频繁调用的 `me_file_identity` 增加局部自动释放池，及时回收格式化字符串；返回值仍是独立的 `strdup` 数据。

Apple 文档确认，未提供目录提示的 [fileURLWithPath:](https://developer.apple.com/documentation/foundation/nsurl/fileurl%28withpath%3A%29?language=objc) 会读取文件系统判断目录；这是本次移除隐式磁盘访问的依据。

## 尚存的短暂停顿

真实应用一次选择 6002 项时，系统剪贴板同步写入在多次运行中约为 0.82–1.35 秒；即使删除应用自身的存在性检查和 URL 隐式探测，仍观察到约 1.32 秒的停顿。独立原生进程分段计时也显示耗时集中在 `NSPasteboard.writeObjects` 和兼容文件列表写入，URL 构造本身约 4ms。

测试把完整操作中超过 1000ms 的主线程心跳间隔记为失败，因此后两次真实窗口报告的 `success` 为 `false`，具体原因是本地多选的系统剪贴板阶段；不是文件内容校验失败。这个残留问题没有被抬高阈值或忽略。外置盘持续传输阶段多次保持响应。
